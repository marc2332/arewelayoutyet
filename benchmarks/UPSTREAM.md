# Benchmark provenance

Copied from [DioxusLabs/taffy](https://github.com/DioxusLabs/taffy/tree/4e59968eda29ceeb0bbaeb3993c8cd38baa3d0a6/benches) at commit `4e59968eda29ceeb0bbaeb3993c8cd38baa3d0a6`, under the MIT license in `LICENSE`.

The upstream templates and original helper modules are unchanged. The manifest retains only the PanGUI benchmark target, removes its unused Parley dependency, and replaces the local Taffy path with that pinned Git revision. The original package name is retained for imports. Daily runs enable Taffy, Morphorm, Torin, Yoga, Clay, Ply, Backer, Cephal, Keru Layout, and our experimental ui_layout adapter. The optional Taffy 0.3 adapter is preserved but not enabled.

The local adapters are `src/ui_layout_helpers.rs`, `src/clay_helpers.rs`, `src/ply_helpers.rs`, `src/backer_helpers.rs`, `src/cephal_helpers.rs`, and `src/keru_layout_helpers.rs`, with module declarations in `src/lib.rs` and registrations in `benches/pangui.rs`. ui_layout is pinned to [cffdbc4bc0e4f54b9a4466847528fbfa2127648a](https://github.com/098orin/ui_layout-rs/tree/cffdbc4bc0e4f54b9a4466847528fbfa2127648a), rather than the published 0.12.1 release, to include its newer wrapping and grid work. The adapter translates templates to flex styles and skips aspect-ratio templates because there is no general aspect-ratio style property.

ui_layout's intrinsic-layout caches are private and have no public invalidation API. Before each timed iteration, its adapter reconstructs every node outside the timer to clear these caches. This also discards scratch buffers, unlike the tree-reusing adapters. Within-pass caching remains enabled. Treat its results as experimental, not a layout-equivalence guarantee.

Clay uses the `clay-layout` 0.4.0 Rust bindings and their bundled C engine. The adapter pre-translates styles and allocates an arena large enough for the complete workload outside timing. Each timed pass includes `BeginLayout`, native element declaration, and `EndLayout`, including render-command generation. Clay computes intrinsic sizes while closing declared elements, so timing only `EndLayout` would exclude part of its layout work. This differs from the retained-tree adapters, whose tree construction is excluded. No render commands are consumed or drawn. Every pass starts a fresh layout, with no text measurement involved.

Clay maps fixed, percentage, fit, and equal-grow sizing, pixel min/max bounds, padding, gaps, and aspect ratios to native properties. It skips child wrapping, in-flow margins, unequal grow weights, and `Expand` minimum sizes. It also rejects unsupported combinations such as min/max bounds on percentage or ratio dimensions and non-integer padding or gaps. Unsupported workloads remain `/`, without silently substituting a different algorithm.

Ply is pinned to the published `ply-engine` 1.1.1 release with default features disabled. The adapter uses the public `engine::PlyContext<()>` directly, without constructing the high-level UI or initializing a Macroquad window, renderer, fonts, accessibility, or input handling. Macroquad remains a compiled dependency. Styles and IDs are pre-translated outside timing. Like Clay, each timed pass includes native begin-layout, element declaration, close-element intrinsic sizing, final layout, and render-command generation. Commands are not consumed or drawn. Layout scratch arrays are rebuilt each frame while text-measurement caches remain unused in these text-free workloads.

The Ply adapter supports 10 of the 13 workloads using fixed, fit, weighted-grow, percentage and aspect-ratio sizing, native child wrapping, pixel min/max bounds, padding, and gaps. It skips in-flow margins and expanding minimum sizes rather than approximating them. The published engine stores each parent's child count in a `u16`, so the 100,000-sibling workload is also skipped. This is a per-parent fan-out limit, not a total-node limit. Fit nesting's 101,111 nodes, including 100,000 full-size leaves, run successfully. The adapter increases the engine's total element capacity for each accepted workload and checks every generated ID's finite bounds, size limits, and aspect ratios before registering it. These safety checks do not establish pixel-identical output across engines.

Backer is pinned to 0.12.0 with no default features or runtime dependencies. Native rows, columns, equal expansion, pixel limits, aspect helpers, and padding wrappers implement the adapter. It accepts seven shared workloads and skips automatic wrapping, unequal main-axis grow weights, parent percentages, in-flow margins, and expanding minimum sizes. Although Backer supports aspect ratios, the combined percentage-and-ratio workload cannot be translated.

Backer's public `min_width` entrypoint runs the complete native layout pipeline, including two resolve/allocation rounds. It is used to time layout without the destructive `draw` collection phase or draw callbacks. Its allocated/resolved state is private and has no reset API, so the adapter prepares a validated specification once and rebuilds the native input tree before each timed iteration. Construction and destruction of the old tree are excluded. Native padding wrappers and algorithm scratch allocations remain part of layout cost. An untimed observer tree checks that every leaf is present, finite, and satisfies its fixed sizes and limits. Separate local geometry checks verified equal expansion, aspect sizing, and all 100,000 fit-nesting leaves at 0.99 by 10 pixels. Input/output collection and callbacks are not timed.

Cephal is pinned to [9e77f9100ab3b2f55ade85dd5f24bb987fd28982](https://github.com/zortax/cephal/tree/9e77f9100ab3b2f55ade85dd5f24bb987fd28982), version 0.2.0. Its native adapter translates all 13 templates using the same flexbox mapping as the Taffy adapter, including weighted expansion, expanding minimum sizes, percentages, aspect ratios, wrapping, margins, padding, and gaps. Tree construction and style translation happen outside timing. Before each iteration, the public `Tree::clear_layout` discards every cached answer and layout outside timing. Only serial `compute_layout` is timed, with default pixel snapping enabled and without custom measurement callbacks or parallel workers. These runs measure cold layout, not Cephal's incremental-update performance, and do not establish pixel-identical output across engines.

Keru Layout uses the author's [benchmark adapter](https://github.com/kekelp/arewelayoutyet/blob/faf56669dad5201ba5f8495f828a2a94b7779691/benchmarks/src/keru_layout_helpers.rs) unchanged, with the same crates.io `keru_layout = "=0.1.0"` dependency and default features. Its compact Vec-backed tree implements the low-level `TreeAdapter` API and adds a synthetic Fill viewport root above the template root. Ten shared workloads are translated using stacks, weighted Fill, FitContent, Frac, AspectRatio, min/max bounds, padding, and gaps. Automatic wrapping and in-flow margins are skipped. Each timed iteration calls the full `solve_layout` entrypoint, including output rectangle writes. Invalidation is a no-op, construction is excluded, and scratch storage is reused. The shared templates and timing harness match the author's fork. No extra validation or high-level LayoutTree wrapper is added. Per-node normalization still uses the shared template count, excluding the synthetic viewport root. Keru Layout's fill constraints do not imply CSS flexbox equivalence.

`src/bin/workload_nodes.rs` counts nodes after expanding the same templates with the benchmark's Rust parser, including the root. The collector records these as per-run `node_counts` for the graph's average ns/node view. Means and confidence bounds are divided by the same workload count, not an engine's internal node count or number of node visits. Historical runs with the identical upstream revision reuse counts from these unchanged templates. Runs without known counts cannot use the per-node view. Raw timings are unchanged.

Templates originate in [PanGUI's layout benchmark article](https://www.pangui.io/blog/05-layout-rework-and-benchmarks/), as attributed upstream.

To update, review and copy the upstream files, update the Git revision here and in Cargo.toml, regenerate Cargo.lock, and check adapter limitations and the feature matrix. Dependencies deliberately do not float nightly.
